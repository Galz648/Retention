Locked for this version.

- **The command-line program is the only client.** No environment variables, no “open this file to see the card.” Tree, queue, card text, and grades all go through the program.
- **The person sees titles and glossary words**, never folder names or card ids. Those stay on disk for the computer.
- **Pure vs impure is a user-facing label.** Pure = no create/append/move/delete. Impure asks permission; default no. If the program cannot ask yes/no, impure commands refuse. No `--yes`.
- **Consent is in the program, not in Session.** Session.grade does not prompt.
- **TypeScript does not emit a binary.** The compiler emits JavaScript. The artifact is Bun compile → one standalone program.
- Threshold, the spaced-repetition library's internal scales, and the name Brightness stay placeholders until evidence. Parked features stay parked.
- **Adaptive parameters are learned, not configured.** Anything that should fit a person — the forgetting / Brightness curves, the scheduler's intervals, how much one review sitting should hold, how card types (recall vs derivation) are paced — comes from that person's event log via a calibrator, never from a config field or a hand-set constant. The calibrator is not built; the design assumes it will be. Clients (e.g. a review-session skill) keep only fixed preferences in config, decide the rest with the user in the moment, and record what actually happened so the calibrator has data. Reaching for a tuning constant is the signal that the value belongs in the log instead.
- **The program is named `retention`.** That is the binary, the package, and the word you type.
- **TTY default is the session TUI.** No args or `session` opens the options menu (Session, Trees, Status) with the build version. `q` leaves. Named for the Session component. `browse` is gone. One-shot and piped commands stay CLI. Tree choice is not held across process invocations. There is no `tree` dump command; where you are in a map is the TUI path (`●`).
- **Experience, not wiring:** list trees by title; each one-shot chooses a tree; grade asks before it writes. Those are how the program must feel, not leftover internals.
- **Feel must stay useful.** Banner, color, completions, and TUI chrome are in scope for the client. They must not appear on piped output and must not bury the queue. Term decks may hang under a knowledge tree in the listing; they stay separate trees for the engine.
- **Trees listing is a nested map.** Aligned columns, tree branches. Piped `trees` prints and returns. TTY `trees` enters the TUI on Trees (the map).
- **Isolated engine commands.** `mastery`, `graph`, and `scheduler` each talk to one engine Tag. The CLI module may load corpus or log; it must not import the other two engines. Session CLI does not compute Brightness itself.
- **Two surfaces.** TTY `session` is a fullscreen TUI. Home is an options menu. **Session** is the due queue, inspect, and grade-with-consent. **Trees** is the map walk with a you-are-here path. Version is visible on help and in the TUI. One-shot commands stay a CLI. Numbered `prompt()` is not the TTY product. n/curses extras are optional. Rust for the client is allowed, not chosen. Engine stays TypeScript. Revisit if a TypeScript client cannot do completions + TUI + color + one binary without pain.
